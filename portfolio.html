Project
01 · Data QA agent
For
CPG manufacturers and retailers with field teams and KAMs
Data
Shelf recognition data by product and by store
Metric
OOS accuracy and OOS level

Data QA agent: keeps each store's assortment targets correct

An OOS report is only as accurate as the list of products that should be on the shelf. That list is updated by hand, so it goes stale. The agent does the updating.

The problem

New product missing from targetsThe KAM forgot to add it. If it is not on the shelf, it never shows up in the OOS report.
Delisted product still in targetsThe retailer decided to drop it, but the KAM did not know or did not tell the team. Field reps keep logging reasons for a product that should not be there.

Impact

8–12%approximate OOS reduction from correct targets
+5–8%approximate further reduction from trust in the data, faster OOS detection and quick diagnosis, especially for new launches
~40%of time spent entering out-of-stock reasons went to products the retailer had already delisted (two projects)
up to 5 minsaved by the field team on every visit

KAMs start using the data because the OOS report stops disagreeing with reality. Trust grows, and so does usage.

02 · Diagnostic agent
For
Analysts and managers in small and mid-sized teams
Job
Diagnose why a KPI missed its target
Scale
Many brands, SKUs, channels and customers

Diagnostic agent: works through the whole portfolio at once

When a plan is missed, an analyst walks a chain of related metrics. On a large portfolio, going through every combination of brand, product, channel and customer by hand is not realistic. The agent follows the same logic, in parallel.

One cause tree, using the analyst's own rules

Many cuts by product and customer, one tree each

The same tree is built for every product × customer cut. Up to 100 copies of the agent run in parallel, and the findings merge into one document with a ranking of causes.

Consolidated ranking

Impact

5–8 hsaved per week on diagnostics
Fasterdecisions: attention goes to fixing problems, not finding them

Large consulting teams work this way. The same approach works for a small team. The main effort is calibrating the logic in the first stages and adapting the agent when the data structure changes.

Planogram agent: the best assortment and layout for every store and category

A planogram is drawn for an ideal store. Real stores have a different number of shelves and racks. The agent looks at the actual photos, joins them with sales data, and builds an optimal assortment and layout for each store and each category.

Ideal planogram vs. real store

The problem

Equipment differs from the idealMost planogram problems are deviations in the number of shelves and racks.
The error compoundsOne deviation sets off a chain reaction. Staff lose understanding of the layout, and shelf execution in that store becomes less accurate.

Impact

30–40% → 70–80%planogram compliance for management
Ready to useretail staff get a planogram adapted to their store, not a generic one
